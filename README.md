# 서비스 접수 데이터 대시보드 요구사항 명세서

- 문서 버전: v1.1
- 작성일: 2026-08-28
- 프로젝트 유형: PoC (Proof of Concept)
- 개발 도구: Cursor AI
- 개발 기간: 2일 (Day 1 오후 ~ Day 2)

---

## 1. 프로젝트 개요

### 1.1 배경
서비스 접수건 데이터(엑셀)를 담당자가 매번 수작업으로 열어 증상별·처리방법별 현황을 분석하고 있음. 반복적이고 규칙이 정형화된 업무로, 자동화를 통해 시간 절약과 정확도 향상이 기대됨.

### 1.2 목적
서비스 접수건 엑셀 데이터를 자동으로 불러와 **센터별 / 증상별 / 조치내역별** 로 집계하고, **일별 현황 조회**, **기간 지정 추이(일별)**, **주간별 추이**를 웹 대시보드에서 확인할 수 있도록 한다.

### 1.3 핵심 가치
- 매일 수작업으로 하던 데이터 집계·분석 시간 절감
- 사람의 실수(집계 누락, 오타 등) 가능성 축소
- 데이터를 근거로 한 빠른 현황 파악

## 2. 범위 (Scope)

### 2.1 포함 범위 (In Scope)
- 구글 드라이브에 업로드된 접수건 엑셀 파일을 대시보드 실행 시 자동으로 불러오기
- 센터별 / 증상별 / 조치내역별 집계
- 특정 일자 선택 시 해당일 접수건 현황(스냅샷) 조회
- 기간(시작일~종료일) 지정 시 일별 추이 조회
- 주간 단위 추이 조회
- 진행상태 필터(기본값: 전체)
- 개인정보 컬럼(고객명, 연락번호, 이동번호, 주소)은 로딩 단계에서 제외
- 거래처명 / 조치내역 중 제외 대상을 사용자가 직접 등록·수정·해제할 수 있는 기능
- 등록된 제외 설정은 저장되어 다음 실행부터 자동 반영

### 2.2 제외 범위 (Out of Scope, 이후 확장 고려)
- 사내 시스템과의 실시간 자동 연동(API 연동)
- 로그인/사용자 권한 관리
- 모바일 전용 UI 최적화
- 알림(이메일/문자) 기능
- 데이터 자동 백업/이력 관리
- Google Gemini API를 활용한 AI 기능 (아래 8장 참고, MVP 이후 선택 확장 항목)

## 4. 데이터 명세

### 4.1 원본 데이터
- 파일 형식: 구글 시트 (원본 업로드는 .xls였으나, 현재 구글 드라이브에 구글 시트 형태로 공유되어 있음)
- 위치: 담당자가 구글 드라이브에 공유 파일로 업로드
- 공유 설정: "링크가 있는 모든 사용자 - 보기 가능"으로 설정 완료 (확인됨)
- 시트 ID: `1jw5lqKXQIxuGt3eAMbUmWj_fJNL1h9ZY`
- 로딩 방식: 대시보드 실행 시마다 아래 export URL로 구글 드라이브에서 자동으로 xlsx 형태로 읽어옴
  ```
  https://docs.google.com/spreadsheets/d/1jw5lqKXQIxuGt3eAMbUmWj_fJNL1h9ZY/export?format=xlsx
  ```
  ```python
  sheet_id = "1jw5lqKXQIxuGt3eAMbUmWj_fJNL1h9ZY"
  url = f"https://docs.google.com/spreadsheets/d/{sheet_id}/export?format=xlsx"
  df = pd.read_excel(url)
  ```
  > 참고: `gid` 값은 특정 시트 탭(하위 탭)을 가리키는 값이다. 위 export URL은 기본적으로 전체 파일을 xlsx로 내려받는다. 시트가 여러 탭으로 나뉘어 있고 특정 탭만 사용해야 한다면 `pd.read_excel(url, sheet_name="탭이름")`으로 지정한다. 시트가 하나뿐이라면 신경 쓰지 않아도 된다.
- 1행 = 접수 1건 기준 (약 2,000건 내외 규모, 지속 증가)

### 4.2 사용 컬럼 매핑

| 대시보드 기준 | 원본 엑셀 컬럼명 | 비고 |
|---|---|---|
| 접수일 | `접수일` | 일별/기간별/주간별 집계 기준 |
| 진행상태 | `진행상태` | 필터용 (기본값: 전체) |
| 센터 | `방문CE센터` | 센터별 집계 기준 (17개 값) |
| 거래처 | `거래처명` | 제외 등록 대상 |
| 증상 | `실장애증상` | 증상별 집계 기준 (조치 후 확인된 실제 증상) |
| 조치내역 | `조치내역` | 조치내역별 집계 기준, 제외 등록 대상 |

### 4.3 제외 컬럼 (개인정보 — 로딩 단계에서 미포함)
- 고객명
- 연락번호
- 이동번호
- 주소

> 위 4개 컬럼은 엑셀을 읽어오는 시점부터 아예 메모리에 올리지 않거나, 즉시 drop 처리한다. 대시보드 화면·집계·저장 데이터 어디에도 남지 않아야 한다.

### 4.4 그 외 컬럼
원본 파일에는 위 표에 없는 약 45개 이상의 추가 컬럼(모델명, 방문CE, 결제 관련 정보 등)이 존재하나, 본 PoC 범위에서는 사용하지 않는다. 향후 확장 시 별도 요구사항으로 추가한다.

## 5. 기능 요구사항

### F1. 데이터 자동 로딩
- 대시보드 접속(실행) 시, 구글 드라이브에 저장된 지정 엑셀 파일을 자동으로 읽어온다.
- 파일을 읽지 못하는 경우(권한 오류, 파일 없음, 네트워크 오류 등) 사용자에게 명확한 오류 메시지를 표시한다.
- 개인정보 컬럼(4.3항)은 로딩과 동시에 제거한다.

### F2. 제외 목록 관리 (사람의 판단이 필요한 단계)
- 화면 내에 "제외 항목 관리" 메뉴/탭을 제공한다.
- 사용자는 아래를 등록할 수 있다.
  - 제외할 거래처명 (거래처 리스트에서 선택 또는 검색하여 등록)
  - 제외할 조치내역 (조치내역 리스트에서 선택 또는 검색하여 등록)
- 등록된 항목은 **수정** 및 **해제(제외 취소)**가 가능해야 한다.
- 등록/수정/해제 내역은 파일(예: `exclusions.json` 또는 `exclusions.csv`)로 저장되어, 다음 대시보드 실행 시 자동으로 반영된다.
- 최초 실행 시(제외 목록이 비어있을 때)는 전체 데이터를 포함한 상태로 동작한다.
- 화면에는 현재 적용 중인 제외 항목 목록을 함께 보여준다.

### F3. 집계 로직
- 필터링(제외 목록 적용, 진행상태 필터, 기간/일자 조건 적용) 이후 데이터를 기준으로:
  - 센터별(`방문CE센터`) 접수건수 집계
  - 증상별(`실장애증상`) 접수건수 집계
  - 조치내역별(`조치내역`) 접수건수 집계
- 각 집계는 표(테이블) + 막대그래프 형태로 함께 표시한다.

### F4. 일자 지정 현황 (스냅샷)
- 날짜 선택 위젯(달력)을 제공한다.
- 특정 하루를 선택하면, 해당 일자에 접수된 건만 필터링하여 F3의 3가지 집계를 표시한다.

### F5. 기간 지정 추이 (일별)
- 시작일/종료일 선택 위젯을 제공한다.
- 지정 기간 내 데이터를 대상으로, **일자별 접수건수 추이**를 라인 차트 또는 막대 차트로 표시한다.
- 동일 기간 내에서 F3 기준(센터/증상/조치내역)별로 상위 항목을 함께 볼 수 있도록 한다. (예: 상위 5~10개)

### F6. 주간별 추이
- 지정 기간(또는 전체 데이터 기간)을 주 단위(월요일 시작 기준)로 묶어 **주별 접수건수 추이**를 차트로 표시한다.

### F7. 진행상태 필터
- 화면 상단(또는 사이드바)에 진행상태 선택 필터를 제공한다.
- 기본값은 "전체"이며, 사용자가 특정 진행상태만 선택해 필터링할 수 있다.
- 이 필터는 F3~F6의 모든 집계/차트에 공통 적용된다.

### F8. 오류 및 예외 처리
- 엑셀 파일 내 결측값(빈 셀)이 있는 경우, 집계 시 "미분류" 또는 "값없음"으로 별도 그룹 처리하여 데이터 누락 없이 표시한다.
- 제외 목록에 등록된 값이 최신 데이터에 더 이상 존재하지 않아도 오류 없이 무시하고 진행한다.

## 7. 화면 구성 (와이어프레임 설명)

### 7.1 전체 레이아웃
- 사이드바: 진행상태 필터, 날짜 선택(일자 지정 / 기간 지정), 메뉴 전환(대시보드 ↔ 제외 항목 관리)
- 메인 화면: 선택된 메뉴에 따라 아래 중 하나를 표시

### 7.2 "대시보드" 화면
1. 상단: 현재 적용된 필터 요약 (예: 진행상태 전체, 조회기간 2026-08-01 ~ 2026-08-27)
2. 탭 구성
   - 탭1. 일자 지정 현황 → 센터별/증상별/조치내역별 표+차트
   - 탭2. 기간 추이(일별) → 일별 라인차트 + 기간 내 집계 표
   - 탭3. 주간별 추이 → 주별 막대차트

### 7.3 "제외 항목 관리" 화면
1. 현재 제외 중인 거래처/조치내역 목록 표시 (표 형태, 각 행에 [해제] 버튼)
2. 신규 제외 항목 추가: 드롭다운(또는 검색창)에서 거래처/조치내역 선택 → [제외 등록] 버튼
3. 저장 시 즉시 파일에 반영, "저장되었습니다" 안내 메시지 표시

## 8. AI(Google Gemini API) 활용 방안 (선택 확장 기능 — MVP 이후)

현재 MVP 범위는 규칙 기반 집계(pandas)만으로 충분히 구현 가능하여 필수 AI 요소는 없다. 다만 아래와 같이 향후 정확도를 더 높이고 싶을 때 Gemini API를 활용할 수 있다.

| 활용 아이디어 | 설명 | 우선순위 |
|---|---|---|
| 유사 표현 자동 정규화 제안 | `증상내역`/`조치내역`처럼 자유 텍스트성 값에 오타·유사 표현(예: "부팅안됨" vs "부팅 안 됨")이 섞여 있을 때, Gemini API로 유사 그룹을 제안받아 사람이 최종 확인 후 매핑 규칙에 반영 | 중 (2단계 확장) |
| 제외 후보 추천 | 거래처/조치내역 중 이상치(테스트성 데이터, 의미 없는 값 등)로 보이는 항목을 Gemini가 후보로 제안 → 사람이 최종 승인 후 제외 목록에 등록 | 낮음 (참고용) |
| 자연어 질의 요약 | "지난주 대비 부팅이상 건수 어떻게 변했어?" 같은 자연어 질문에 대해 집계 결과를 Gemini가 요약 문장으로 설명 | 낮음 (2단계 확장) |

> 중요: 위 기능은 모두 **"제안"** 수준으로만 사용하고, 실제 데이터 반영(제외 처리, 정규화 매핑)은 반드시 사람이 검토 후 확정하도록 한다. (앞서 확인된 "사람이 직접 판단해야 하는 단계"와 원칙 일치)

## 10. 적합한 기술 방식 추천 및 이유

| 영역 | 추천 기술 | 추천 이유 |
|---|---|---|
| 개발 언어 | Python | 데이터 처리(pandas)와 웹 UI(Streamlit)를 하나의 언어로 통합 개발 가능, Cursor AI와의 궁합이 좋아 이틀 내 빠른 구현에 적합 |
| 웹 UI | Streamlit | 별도 프론트엔드 프레임워크(React 등) 없이 Python 코드만으로 표·차트·필터·업로드 UI를 빠르게 구성 가능. 비개발자도 실행 파일을 다루기 쉬움 |
| 데이터 처리 | pandas | 엑셀 로딩, 그룹핑(`groupby`), 필터링, 일별/주별 집계에 표준적으로 사용되는 라이브러리로 안정성과 레퍼런스가 풍부함 |
| 구글 드라이브 연동 | `gspread` + `google-api-python-client` (또는 공유 링크 기반 `pandas.read_excel(직접 다운로드 URL)`) | PoC 단계에서는 별도 서버 인증 없이 "공유 링크(누구나 보기)" 방식이 가장 빠르게 구현 가능. 이후 보안 강화 시 서비스 계정 인증 방식으로 전환 가능 |
| 차트 | Streamlit 내장 차트(`st.bar_chart`, `st.line_chart`) 또는 `plotly` | 내장 차트는 설정이 간단해 MVP에 적합하며, 더 세밀한 시각화가 필요하면 `plotly`로 손쉽게 교체 가능 |
| 제외 목록 저장 | 로컬 JSON 파일 (`exclusions.json`) | 별도 데이터베이스 설치 없이 파일 하나로 지속성(persist)을 확보할 수 있어 PoC 규모에 가장 단순하고 빠름 |
| AI 확장(선택) | Google Gemini API (`google-generativeai` 파이썬 SDK) | 요청 조건(머신러닝 필요 시 Python 라이브러리/API 활용)에 부합하며, 별도 모델 학습 없이 API 호출만으로 텍스트 유사도 제안 등 구현 가능 |

### 11.2 필수 파이썬 패키지
아래 명령어로 한 번에 설치:
```bash
pip install streamlit pandas openpyxl xlrd plotly
```
| 패키지 | 용도 |
|---|---|
| `streamlit` | 웹 대시보드 UI 구성 |
| `pandas` | 엑셀 데이터 로딩 및 집계 |
| `openpyxl` | `.xlsx` 파일 읽기 지원 |
| `xlrd` | 구버전 `.xls` 파일 읽기 지원 (첨부 원본 파일이 `.xls` 형식이므로 필수) |
| `plotly` | (선택) 세밀한 차트가 필요할 경우 |

### 11.3 구글 드라이브 연동 준비 (확인 완료)
공유 설정이 "링크가 있는 모든 사용자 - 보기 가능"으로 이미 적용되어 있음을 확인했다. 아래 순서로 바로 사용 가능하다.

1. 구글 시트 공유 링크에서 파일(시트) ID 확인 (링크 중 `/d/` 와 `/edit` 사이의 문자열)
   - 확인된 시트 ID: `1jw5lqKXQIxuGt3eAMbUmWj_fJNL1h9ZY`
2. 아래와 같은 다운로드 전용 URL 형태로 pandas에서 바로 읽기
   ```python
   sheet_id = "1jw5lqKXQIxuGt3eAMbUmWj_fJNL1h9ZY"
   url = f"https://docs.google.com/spreadsheets/d/{sheet_id}/export?format=xlsx"
   df = pd.read_excel(url)
   ```
3. (테스트 방법) 시크릿(비공개) 브라우저 창에서 위 export URL로 접속했을 때 로그인 창 없이 곧바로 xlsx 파일이 다운로드되면 공유 설정이 정상인 것이다. (확인 완료)
4. (참고) 사내망 등 보안상 "링크 공개"가 어려운 경우, 구글 서비스 계정(Service Account)을 생성하고 `google-api-python-client`, `google-auth` 패키지를 추가로 설치하여 인증 기반 접근으로 전환 필요 — 이 경우 별도 설정 시간이 추가로 소요되므로 이틀 일정에는 1~2번 방식(공개 링크)을 우선 권장

### 11.4 Gemini API 준비 (8장 확장 기능을 시도할 경우에만 필요)
| 항목 | 준비 방법 |
|---|---|
| Gemini API 키 발급 | [Google AI Studio](https://aistudio.google.com/) 접속 → 로그인 → API 키 생성 |
| 패키지 설치 | `pip install google-generativeai` |
| API 키 보관 | 코드에 직접 입력하지 않고, `.env` 파일 또는 Streamlit의 `secrets.toml`에 저장 후 코드에서 불러와 사용 (`pip install python-dotenv` 추가 설치 권장) |

### 11.5 실행 확인
모든 설치가 끝나면 아래 명령어로 정상 실행 여부를 확인한다.

streamlit run app.py

### 1단계. 데이터 로딩 + 개인정보 제거 (F1)

대시보드의 기반이다. 이후 모든 집계가 이 데이터에 의존한다.

| 작업 | 내용 |
|---|---|
| 시트 로드 | export URL → `pd.read_excel()` |
| 컬럼 상수화 | `접수일`, `진행상태`, `방문CE센터`, `거래처명`, `실장애증상`, `조치내역` |
| 개인정보 즉시 제거 | `고객명`, `연락번호`, `이동번호`, `주소` — 로드 직후 drop |
| 미사용 컬럼 제거 | 집계에 쓰지 않는 약 45개 컬럼도 이 단계에서 정리 |
| 오류 메시지 | 권한/네트워크/파일 오류 시 사용자에게 명확히 안내 |
| 날짜 정규화 | `접수일`을 datetime으로 변환 |

> **완료 기준:** 개인정보 없이 필요한 컬럼만 메모리에 올라오고, 실패 시 에러 화면이 나온다.

- [ ] 센터별 / 증상별 / 조치내역별 건수 (`groupby` + `count`)
- [ ] 결과는 표와 막대차트에 바로 넣을 수 있는 형태로 반환

> **완료 기준:** 전체 데이터 기준으로 3종 집계 표가 나온다. (필터는 아직 없음)

### 7단계. 제외 항목 관리 (F2)

집계가 안정된 뒤에 넣는 기능이다. "사람의 판단"이 들어가는 유일한 화면이다.

| 작업 | 내용 |
|---|---|
| 저장소 | `exclusions.json` (거래처명 / 조치내역 목록) |
| 화면 | 현재 제외 목록 표 + 행별 [해제] |
| 추가 | 드롭다운/검색 → [제외 등록] |
| 수정·해제 | 즉시 파일 저장 + "저장되었습니다" 안내 |
| 집계 연동 | 로드 후, 등록된 거래처·조치내역 행은 집계에서 제외 |
| 예외 | 원본에 없는 제외 값은 오류 없이 무시 (F8) |

최초 실행(파일 없음/빈 목록)은 **전체 데이터**로 동작한다.

> **완료 기준:** 제외 등록 → 새로고침 → 집계에서 빠지고, 해제하면 다시 포함된다.

### 1단계. 데이터 로딩 + 개인정보 제거 (F1)

- export URL → `pd.read_excel()` (openpyxl)
- 필수 컬럼: `접수일`, `진행상태`, `방문CE센터`, `거래처명`, `실장애증상`, `조치내역`
- 개인정보(`고객명`, `연락번호`, `이동번호`, `주소`)는 `usecols`로 메모리에 올리지 않음
- **요구사항과 다른 점:** 미사용 컬럼은 삭제하지 않고 유지함. PII 제외 후 **51개 컬럼**
- 권한/네트워크/파일/형식 오류 시 한국어 안내 후 중단
- `접수일`을 datetime으로 변환. 변환 실패 행은 일자 집계에서 제외하고 건수를 안내

### 2단계. 집계 엔진 (F3)

- 빈 셀·공백 → `"미분류"`
- 센터별 / 증상별 / 조치내역별 건수 (`groupby`)
- 표·막대차트에 바로 넣는 형태로 반환 (`AggregationView`)
- 이후 기준관리에서 컬럼을 바꾸면 같은 엔진이 동적 기준을 집계함

### 3단계. 일자 지정 현황 (F4)

- 사이드바 조회일(달력). 기본값은 데이터 마지막 날
- 선택한 하루의 접수건만 필터 후 집계 표 + 막대차트
- 상단에 조회일·건수 요약

확인 예: 2026-08-27 전체 204건, 서비스완료 58건

---

### 4단계. 진행상태 필터 (F7)

- 사이드바 진행상태. 기본값 **전체**
- 일자 현황, 기간 추이, 주간 추이에 공통 적용
- 상단 요약에 현재 진행상태 표시

---

### 5단계. 기간 지정 일별 추이 (F5)

- 사이드바 시작일 / 종료일. 기본은 데이터 전체 기간
- 기간 합계·일평균·조회 일수
- 기준별 탭: 왼쪽 순위 표(행 클릭) + 오른쪽 일별 라인 차트
- 행을 클릭하면 해당 항목만 일별 추이. 선택 해제로 전체 추이 복귀
- 0건인 날짜도 추이에 포함

추가 요청으로 반영한 것: 기간별 건수와 일별 추이를 같이 보기, 표 행 클릭 시 항목별 일별 추이

---

### 6단계. 주간별 추이 (F6)

- 구현 순서상 한 차례 건너뛴 뒤 **8단계에서 탭3으로 넣음**
- 월요일 시작 주 단위. 라벨 예: `2026-08-03 ~ 08-09`
- 기간은 사이드바 시작일·종료일 재사용
- 주별 막대차트. 상세 표는 접어서 표시
- 진행상태 필터 적용. 기간 내 주 합계는 접수건수와 일치 (전체 1,970건 / 5주)

### 7단계. 제외 항목 관리 (F2)

- 저장: `exclusions.json`
- 화면: 등록된 값 목록 + 행별 **해제**, 검색/선택 후 **제외 등록**
- **요구사항과 다른 점:** 값 **수정** 기능은 빼고 등록/해제만 둠
- 센터도 제외 대상에 추가 (이후 10단계에서 기준 목록과 연동)
- 원본에 없는 제외 값은 오류 없이 무시
- 목록이 비어 있으면 전체 데이터로 집계
- 예전 JSON 키(`센터`, `거래처명` 등)는 원본 컬럼명으로 읽어 호환

### 8단계. 화면 구성·사용성

- 사이드바: 메뉴 → 조회 조건(진행상태, 조회일, 시작일/종료일) → 데이터 다시 불러오기
- 대시보드 탭: 일자 지정 현황 / 기간 추이(일별) / 주간별 추이
- 원본 데이터 정보는 화면 아래 expander로 접음
- `st.cache_data`로 시트 로딩 캐시. 집계 자체는 약 2,000건 기준 수십 ms
- 첫 다운로드는 네트워크에 따라 수 초 걸릴 수 있음

### 9단계. 예외 처리·최종 점검 (F8)

- 빈 셀 → 미분류 그룹
- 로딩 실패·예상 밖 오류는 한국어 메시지로 표시
- 제외 값이 원본에 없어도 동작
- 개인정보 컬럼이 남아 있으면 화면을 그리지 않음
- 제외/기준 파일이 깨져 있으면 전체 데이터(또는 기본 기준)로 진행하고 경고
- Day 1~2 기능(F1~F8) 동작 확인

### 10단계. 기준관리 (추가 기능)

12장에는 없던 기능이다. 집계 기준 컬럼을 사용자가 추가·삭제한다.

- 메뉴: **대시보드 / 기준관리 / 제외 항목 관리**
- 기본 등록: 센터(`방문CE센터`), 증상(`실장애증상`), 조치내역
- 기준에 있는 컬럼만 대시보드 집계와 제외 항목 메뉴에 나타남
- 기준에서 빼면 제외 메뉴에서도 사라지고, 그 컬럼의 제외값은 **즉시 무효**(파일에서도 삭제)
- 거래처명은 기본 기준이 아님. 기준관리에서 넣어야 집계·제외에 나오고, 예전에 저장한 거래처 제외값도 그때 다시 적용됨
- 접수일·개인정보 컬럼은 기준으로 추가할 수 없음
- 저장: `criteria.json`

Streamlit이 예전 `dashboard_config`를 붙잡고 `CRITERIA_FILE_NAME` import 오류가 난 적이 있어, `app.py`에서 설정 모듈을 먼저 `reload`한 뒤 나머지 모듈을 읽도록 수정함.

### 13단계. 요약 카드 글자 크기·반응형 (추가)

상단 요약(진행상태 / 조회일 / 조회기간 / 제외)과 기간·주간 탭의 숫자 카드가 좁은 화면에서 `...`으로 잘리던 문제를 고침.

- 조회기간 값이 칸보다 길면 글자 크기를 줄여 전체가 보이게 함
- 같은 화면의 다른 숫자 카드도 조회기간과 글자 크기를 맞춤
- 브라우저 너비가 바뀌면 카드 칸 너비에 맞춰 글자 크기가 같이 변함 (`clamp` + 칸 넘침 시 자동 축소)
- 잘림 표시(`...`)는 쓰지 않음

### GitHub에 올릴 때

현재 원격 저장소는 [yonsisound/dashboard](https://github.com/yonsisound/dashboard) 이다.

폴더 안에는 가상환경(`venv`) 때문에 파일이 1만 개가 넘는다. **소스만 올리면 11개**이며, `venv`는 올리지 않는다. GitHub 웹에서 폴더 통째로 올리면 업로드가 실패한다.

올릴 파일:

- `.gitignore`
- `app.py`, `aggregator.py`, `criteria.py`, `dashboard_config.py`, `data_loader.py`, `exclusions.py`
- `criteria.json`, `exclusions.json`
- `README.md`, `requirements.txt`

다른 PC에서 받은 뒤 실행:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
